1. Introduction

1.1 What this guide is for

This guide explains how to use Dynamics Queue Admin, the web console that a loading place — a queue organization such as a customs terminal, factory, cement yard, depot, mine, farm or port — uses to run its vehicle dispatch queue on the Dynamics freight marketplace. It takes you from creating the loading place and signing in, through checking drivers in, dispatching vehicles to orders, managing orders and shipper requests, bidding on behalf of shippers, reading reports, watching the live connection, using the security compliance view, and adjusting settings, language and appearance.

1.2 Who uses the console

The console is used by staff of a registered queue organization. Two queue-staff roles are defined for day-to-day work; platform administrators may also sign in for oversight and approval.

Role Role ID What they do in the console
Queue Organization Admin 11 Owns the loading place: profile and members, queue operations, orders, bidding on behalf of shippers and reports. Can approve or suspend the organization (queue admins only).
Queue Dispatcher 12 Runs day-to-day queue operations: checks drivers in, dispatches vehicles, overrides and removes entries, and handles orders and shipper requests. Cannot open bidding on behalf of shippers.
Platform Admin / Super Admin 3 / 6 Signs in for oversight: reviews queue organizations, approves, suspends or rejects them, and views the same operational screens.

1.3 What the console does

  • Registers a loading place (queue organization) and its location as a queue gate.
  • Checks drivers into the queue and assigns each one a queue position.
  • Dispatches waiting vehicles to orders, with override and removal controls.
  • Creates and manages orders and shipper requests for the loading place.
  • Opens bidding on behalf of shippers and accepts a driver bid for the owning organization.
  • Reports on drivers, waiting vehicles, orders and organizations.
  • Tracks the live queue connection and shows real-time updates.
What the console does not do

This console is one part of the Dynamics platform. It is not the driver mobile application or the shipper application, it does not process payments, and it does not provide a live GPS feed. Where a capability is absent or disabled, this guide says so plainly. See §14 (settings that are not enabled) and §16 (troubleshooting).

1.4 Before you begin

  • Your loading place must be registered, and approved by an administrator, before drivers can be dispatched.
  • You need a supported modern browser (Chrome, Edge, Firefox or Safari).
  • You need the mobile number registered to your account to receive a one-time code.
  • To create an order you need the shipper's phone number, the cargo, the quantity in quintals, the vehicle type and the pickup and delivery places.

3. Signing in

Access to the console is by phone number and a one-time code (OTP) sent to that phone. There is no password and no role selection — the role is a property of your account. This keeps access tied to the number registered to your organization.

3.1 Enter your phone number

  1. Open the console. The sign-in screen appears.
  2. Enter your Ethiopian mobile number. The console validates the international format +251 followed by nine digits.
  3. Select Sending OTP / Send OTP to request the code.

[Screenshot: Login screen — phone number field with the +251 country code and a partially entered number, with the Send OTP button]

3.2 Enter the one-time code

  1. A screen asks for the six-digit verification code sent to your phone.
  2. Type the six digits. The code boxes accept digits only, move focus forward as you type, and move back when you press backspace. You can also paste the whole code and it is distributed across the boxes.
  3. When the sixth digit is entered the code is submitted automatically and you are signed in.
  4. If the code does not arrive, wait for the resend countdown to finish (60 seconds), then choose Resend OTP.
  5. To change the number you started with, use the back arrow.

[Screenshot: OTP verification screen — six digit boxes with a code entered, the resend countdown, and the Verify button]

Field / control Rule
Phone number Required. Ethiopian international format: +251 plus 9 digits.
Verification code Required. Exactly 6 digits. Submitted automatically when the sixth digit is entered.
Resend OTP Available after the 60-second countdown expires; sends a fresh code to the same number.

3.3 Sessions and signing out

  • Sign-in establishes a secure, HTTP-only session cookie. No access token is stored in or exposed to the browser's JavaScript, and there is no separate refresh step.
  • Session lifetime depends on the role: platform administrators (roles 3 and 6) are signed out after 24 hours; queue staff (roles 11 and 12) remain signed in for up to 365 days.
  • If your session ends, you are returned to the sign-in screen and must request a new code.
  • To sign out, open your account area or go to Settings → Sign Out (§14).
Role Session lifetime
Queue Organization Admin (11), Queue Dispatcher (12) 365 days
Platform Admin (3), Super Admin (6) 24 hours
Keep your number current

The one-time code is sent to the mobile number on the account. If your number changes you will not be able to sign in until it is updated on the account.

4. Creating and registering a loading place

A loading place is a queue organization — the site whose vehicle queue you manage. It must be created before the queue board is available, and it must be approved by an administrator before drivers can be dispatched.

4.1 Create the organization

  1. On first sign-in, if your account has no organization yet, the console opens the Setup Organization screen (also shown as a Create Organization dialog from the dashboard).
  2. Enter the organization name (for example, "Addis Freight Terminal").
  3. Choose the organization type from the list below.
  4. Optionally enter a contact phone number for the loading place.
  5. Enter the address and select the matching suggestion from the address search. Selecting a suggestion records the location's latitude and longitude — this location is the site reference used by the queue and as the check-in gate.
  6. Select Create Organization. A new organization starts in pending approval status.

[Screenshot: Setup Organization screen — name, type, phone, and address search with a selected suggestion showing the resolved location]

Field Required Notes
Organization name Yes The display name used across the console.
Organization type Yes One of the types listed in §4.2.
Contact phone No Ethiopian format, +251 plus digits.
Address (with location) Yes Chosen from the address search; the selected suggestion supplies the latitude and longitude that define the site location.

4.2 Organization types

The console accepts one of the following loading-place types.

Check-in radius

The check-in gate uses a radius around the organization's location. The radius is a system setting (default 15 km) applied by the platform; it is not entered on the create-organization form. If your operational radius needs to differ from the default, raise it with the platform administrator.

4.3 Approval statuses

Each organization has an approval status shown as a badge on the manage page and the organization list.

Status Meaning
Pending Newly created; awaiting administrator review. The queue is not enabled.
Approved The organization is enabled and its queue is live.
Rejected The application was declined by an administrator.
Suspended An approved organization whose queue has been disabled by an administrator.

4.4 Managing a loading place

Open Organizations and select a loading place to open the manage page. It contains the organization profile, the member list, and — for queue administrators — the approval controls.

  • Profile — update name, type, phone and address/location. Saving a new address updates the site location.
  • Members — add a member by user identifier and role, and deactivate, reactivate or remove members. Membership itself is the permission, so a lifecycle change takes effect on the member's next request.
  • Approval (queue administrators only) — Approve, Suspend or Reject the organization. Approving enables the queue; suspending or rejecting disables it.

[Screenshot: Manage Organization page — profile form, members table, and the approval actions available to a queue administrator]

Approval is required before dispatch

Drivers can only be dispatched once the organization's status is Approved. While it is pending, rejected or suspended, use the queue board for preparation only.

5. The dashboard

The dashboard is where you choose which loading place to work in and see your organization's summary. It is the landing page after sign-in.

5.1 The organization overview

  • Organization cards — each loading place you can access is shown with its type, name and approval badge. Select one to open its live queue.
  • Create organization — opens the same create dialog described in §4 for accounts that can add another loading place.
  • Summary figures — the overview shows the organization's operating figures, including drivers, waiting vehicles and orders.

[Screenshot: Dashboard — organization list with approval badges and the overview summary figures]

Dashboard figures are computed in the console

The summary figures shown on the dashboard and in Reports are calculated in the console from the data it has loaded. They are suitable for operational monitoring; treat them as working figures rather than an audited source of record. See §11.

6. The live queue board

The live queue board (Live Queue) is the operational heart of the console. It shows the vehicles currently in the queue for the selected loading place, grouped by vehicle type, and lets you check drivers in and dispatch them.

6.1 The board header

  • Live / Connecting badge — a coloured badge next to the title shows whether the real-time connection is live. See §12.
  • New Order — opens the create-order dialog (§9).
  • Manual Check-in — opens the check-in dialog to add a driver to the queue (§7).

6.2 Vehicle-type cards

The board shows one card per vehicle type that has drivers in the queue, plus a card for all drivers. Each vehicle-type card shows the number of waiting vehicles and a Dispatch button.

  • Dispatch is enabled only when there is at least one waiting vehicle for that type. When the waiting count is zero the button is disabled.
  • The All Drivers card lists every driver in the queue regardless of vehicle type.
  • Select a card to open the queue table for that vehicle type.

[Screenshot: Live queue board — vehicle-type cards with waiting counts and Dispatch buttons, plus the All Drivers card and the Live badge]

6.3 The queue table

The queue table lists each driver in the queue with their assigned position. On narrow screens the table is replaced by stacked cards that carry the same information.

7. Check-in

Check-in adds a driver to the queue. Use the Manual Check-in action on the queue board to open the check-in dialog.

7.1 Checking a driver in

  1. On the live queue board, select Manual Check-in.
  2. Search for the driver. The search covers the driver directory and the current queue, and matches on the details shown for each driver (such as name and phone).
  3. Select the driver from the results.
  4. Optionally enter a queue number to place the driver at a specific position. If you leave it blank, the driver is appended to the end of the queue by the usual first-in, first-out (FIFO) rule.
  5. Confirm the check-in. The driver appears on the queue board with their position.

[Screenshot: Check-in dialog — driver search results, the selected driver, and the optional queue number field]

Positions and the optional queue number

Leaving the queue number empty means the platform assigns the next FIFO position. Enter a number only when you deliberately need to place a driver at a specific position; the override action (§8.3) is available later if you need to correct a position.

8. Running the queue

This section covers the day-to-day operations on the queue board: dispatching, overriding a position, removing an entry, and reviewing an entry's history.

8.1 Dispatching a vehicle

  1. On the queue board, find the vehicle-type card with waiting drivers.
  2. Select Dispatch (enabled only when at least one vehicle is waiting).
  3. In the dispatch dialog, choose the order to dispatch the front waiting vehicle to. The dialog shows a summary of the shipper request for the selected order.
  4. Confirm. The vehicle is dispatched and its status changes accordingly.

[Screenshot: Dispatch dialog — order selection and the shipper-request summary for the chosen order]

8.2 Dispatch is tied to waiting vehicles

The Dispatch button on a vehicle-type card is disabled whenever that card's waiting count is zero. To dispatch, first check a driver in (§7) or select a different vehicle-type card that still has waiting vehicles.

8.3 Overriding a position

  1. Open the row action for the driver and choose Override.
  2. Enter the new queue number and a reason for the change.
  3. Confirm. The driver's position is updated and the change is recorded.

[Screenshot: Override dialog — new queue number and reason field]

8.4 Removing an entry

  1. Open the row action for the driver and choose Remove.
  2. Enter a reason when prompted and confirm.
  3. The driver is removed from the queue. The reason is communicated to the affected party through the live connection.
Removal reasons

The removal dialog asks for a reason and the reason text is broadcast to the queue's live listeners. Enter a clear, factual reason so the driver's app reflects an accurate explanation.

8.5 Entry history

Each queue entry keeps an immutable history. Open the row action and choose History to see the recorded before-and-after snapshots for the entry — for example, its original position and any later override.

[Screenshot: Entry history dialog — before/after snapshots for a queue entry]

9. Orders and shipper requests

The Orders area lists the orders and shipper requests for your loading place, and is where you create new orders and review driver requests against a shipper's request.

9.1 Creating an order

  1. On the queue board select New Order, or use the create action in the Orders area.
  2. Choose the Request Type: individual target (a specific vehicle slot) or company target (open to carriers).
  3. Choose the Dispatch Mode: FIFO Queue (auto-offer to the front waiting driver) or Open for Bidding (a biddable job for carriers).
  4. Enter the shipper's phone number and choose the vehicle type.
  5. Enter the cargo details: item, quantity in quintals, cost, number of vehicles, and the shipping and delivery dates. Quantity per vehicle cannot exceed the selected vehicle type's carrying capacity.
  6. Enter the origin and destination by searching the address field and selecting the matching suggestion, which records the coordinates for each place. The origin defaults to the loading place's location.
  7. Select Create Order. The order is created and offered to the queue.
Field Notes
Request Type Individual target or company target.
Dispatch Mode FIFO Queue, or Open for Bidding (see §10).
Shipper phone Ethiopian format, +251 plus digits.
Vehicle type Selects the queue lane the order is dispatched on.
Cargo and quantity Capped by the selected vehicle type's capacity.
Cost and dates Shipping and delivery dates; the shipping date cannot be in the past.
Origin / destination Address search records place names and coordinates.

[Screenshot: Create Order dialog — request type, dispatch mode, shipper, vehicle type, cargo, and origin/destination with map coordinates]

Large orders default to company target and bidding

When the number of vehicles for an individual order is set above nine, the console automatically switches the request to a company target and turns on open bidding. This is by design — very large volumes are offered to carriers rather than a single queue slot.

9.2 The orders list

The orders list shows each order with its identifier, shipper, vehicle type, cargo, route, quantity and cost. Multi-vehicle orders are grouped into a single batch row that summarises the vehicles and their journey stages, and can be expanded to show each vehicle.

  • Journey stage — each order shows its current stage (for example, accepted, loading, in transit, completed). See §17 for the journey-status glossary.
  • Bidding indicator — orders that are open for bidding are marked as such.

[Screenshot: Orders list — an expanded multi-vehicle batch row showing individual vehicles and their journey stages]

9.3 Shipper requests and driver acceptance

  1. Open a shipper's request to see its overview (cargo, route, dates and status).
  2. If there are driver requests against it, each is listed with the driver's details and offer.
  3. Select Accept on a driver request to accept that driver for the shipper request. Repeat for other drivers as needed.
  4. Use View All Orders to open the full orders list filtered to that shipper.

[Screenshot: Shipper requests dialog — request overview and the list of driver requests with Accept actions]

10. Bidding on behalf of shippers

When an order is opened for bidding, carriers/drivers place offers. As the queue organization you review the offers on the shipper's behalf and accept the driver you judge best.

10.1 Who can open bidding

Bidding is restricted

The bidding control is available only to the Queue Organization Admin (role 11) for an order that belongs to their organization, and to the Super Admin (role 6). A Queue Dispatcher (role 12) does not see the control, and the platform refuses the action if attempted — a dispatcher can still run the queue and orders, but cannot open bidding on a shipper's behalf.

10.2 Opening an order for bidding

  1. In the Orders area, select the order you want to open for bidding.
  2. Use the bid toggle to turn bidding on for that order.
  3. The toggle itself is per order: an order either has bidding approved or not. Turning it on publishes the order as a biddable job for carriers.

10.3 Reviewing offers and accepting a driver

  1. Open the order's driver bids.
  2. Use the toolbar to search by driver name, phone or plate, choose a sort order, and set a display limit.
  3. Compare the offers. Each offer shows the driver's details, their offer, and — where available — distance and vehicle information.
  4. Select Accept on the offer you want. The console accepts that specific driver's bid.
Sort option Orders offers by
Nearest Distance First Closest driver to the pickup.
Lowest Offer First Lowest offer amount.
Highest Offer First Highest offer amount.
Driver Name (A–Z) Driver name, alphabetically.
Default Order The platform's default ordering.

[Screenshot: Driver bids board — toolbar with search, sort and display limit, and the list of driver offers with Accept actions]

10.4 Bid statuses

Status Meaning
Selected The bid was accepted for the order.
Not selected The bid was reviewed but not accepted.
Withdrawn The driver withdrew the bid before a decision.

12. Real-time notifications and connection status

The console keeps a live connection to the platform so that queue changes — check-ins, dispatches, removals, bids and organization updates — appear without a manual refresh.

12.1 The live connection

  • The queue board shows a Live badge when the real-time connection is open, and a Connecting badge while it is re-establishing.
  • Queue staff (roles 11 and 12) receive queue events through a shared queue-organization channel, so both administrators and dispatchers see the same live updates.
  • When the connection drops, the console shows a disconnected state and automatically retries. It makes up to five reconnection attempts with a short delay between them (starting at about 1.5 seconds and backing off up to about 5 seconds).
  • If the retry delivers the underlying data again, the board returns to Live and refreshes the affected lists.

[Screenshot: Live queue board showing the Connecting / disconnected state and the returning Live badge]

12.2 What triggers a live update

  • A driver checking in or being removed from the queue.
  • A vehicle being dispatched or its position overridden.
  • An order or shipper request changing, or a bid being placed or accepted.
  • An organization being approved, updated or its members changing.
If the badge stays on Connecting

Check your network connection and try reloading the page. If your session has expired, the connection is closed deliberately and you are signed out — sign in again with a one-time code (§3). See §16 for more.

13. Security compliance view

The Security area presents the console's INSA security compliance information. It is a reference and tracking view; it does not change the security of the running system.

13.1 The tabs

Tab Shows
Overview A summary of the compliance position and counts.
Requirements The INSA requirements grouped by the five focus areas.
Vulnerabilities The tracked vulnerabilities and their status.
Testing The security test checklist with pass/fail tracking.

13.2 Tabs, requirements and testing

  • The standard is organised into five focus areas (numbered 2.1 to 2.5), with a set of requirements and tests and a set of tracked vulnerabilities.
  • In the Testing tab you can mark each test as passed or failed. The counts and progress shown on the page are computed from those marks.
Where test tracking is stored

Pass/fail marks you record in the Testing tab are saved in this browser (local storage). They persist across reloads on the same browser and device, but they are not shared between users, browsers or devices. Selecting a test's active status again clears it; a test with no mark is shown as untested. Treat the marks as a local working checklist for this submission.

14. Settings

Settings is where you control your account, language and appearance for the console.

14.1 What you can change

  • Language — switch the interface between English and Amharic (§15).
  • Appearance — switch between light and dark theme (§15).
  • Sign Out — end your session and return to the sign-in screen.

14.2 Account options that are not enabled

Disabled in this release

Profile editing, notification preferences and two-factor authentication appear in the account area but are not enabled in this release, and are shown with an explanatory label. There is no server-side endpoint behind them, so they do not save any change. Do not rely on them to update your account; contact the platform administrator for account changes.

14.3 Danger zone

A danger zone provides an account-deletion action, protected by a confirmation dialog. This is a destructive, account-level action; use it only when the account is genuinely to be removed.

16. Troubleshooting and FAQ

16.1 Common situations

Symptom What to do
I did not receive the one-time code. Wait for the 60-second countdown and select Resend OTP. Confirm the number is correct for your account.
I am signed out unexpectedly. Administrator sessions last 24 hours. Sign in again with a fresh code; queue staff sessions last much longer.
The Dispatch button will not activate. That vehicle-type card has no waiting vehicles. Check a driver in (§7) or choose a card with waiting vehicles.
I cannot find the bidding control. Bidding is only available to the queue administrator (and Super Admin) for their own organization; dispatchers do not see it (§10.1).
The Live badge stays on Connecting. Check your network, then reload. If your session expired you will be returned to the sign-in screen (§12).
My theme or language reset. These are saved per browser and device; they do not follow your account. Set them again in Settings (§15).
My profile or notification changes do not save. Those options are disabled in this release and have no server endpoint (§14.2).
The reports figures look different from another screen. Report figures are computed in the console from loaded data and are working values (§11). Refresh to load the latest data.

16.2 Frequently asked questions

  • Can I sign in with a username and password? No. Access is by phone number and one-time code only.
  • Can a dispatcher open bidding? No. Only the queue administrator for the owning organization (and the Super Admin) can.
  • Where is my check-in radius set? It is a platform setting (default 15 km), not a field on the organization form (§4).
  • Are the security checklist marks shared with my team? No. They are stored in your browser only (§13).
