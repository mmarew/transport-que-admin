Secure Website Management Standard

Version 1.0 · 2014 EC · Information Network Security Agency (INSA)

Purpose

The standard assists government and key private organizations in integrating security features into their website design, implementation, hosting, operation, and management based on the services they provide, and provides applicable requirements to prevent the most common security threats to websites.

Scope

This standard is applicable to Ethiopian federal and regional government and key private organizations of the country.

Principles

Guiding principles for website design, implementation, hosting, operation and management

  • Mission-oriented

    Websites should reflect organizations' business requirement and they should be developed and managed in a way that helps organizations achieve their mission.

  • Simplicity

    Websites should be simple for users and administrators/managers.

  • Accessibility

    Websites should be accessible at any time and place using any device.

  • Risk-based

    The security controls implemented on websites should be based on thorough risk assessment results.

  • Integrate security

    Security features should be integrated at each component of the website while designing, implementing, hosting, operating, and managing it.

Focus Area Requirements

Minimum security requirements per website lifecycle focus area

2.1 Requirement Gathering and Analysis 2 mandatory 8

The objective of the requirement gathering and analysis is to organize, analyze, and reflect the intents of the organization's website while developing and managing.

  • RGA-A SHOULD

    The business requirement gathering should comprise the most fundamental issues that address the organization's missions, business objectives, and acceptable risk criteria.

  • RGA-B SHOULD

    The gathered organizational business requirement should be relevant and provide reliable information in alignment with the requirement A.

  • RGA-C SHOULD

    The requirement should include security objectives and needs of all relevant stakeholders.

  • RGA-D SHOULD

    The requirements should provide details of how the website should behave securely and specify what is needed to be done during design, implementation, hosting, operation, and management.

  • RGA-E SHOULD

    The requirements gathering document should address post implementation security needs of stakeholders such as about hosting, operation, and management of the website.

  • RGA-F SHOULD

    The requirement analysis should be unambiguous, and recorded as organizational asset.

  • RGA-G MUST

    Contracts with developers must consider the protection of the intellectual property of source code to protect organizational interests.

  • RGA-H MUST

    Security requirements must be approved by top management of the organization or relevant business owner.

2.2 Design 2

The objective of this focus area is to define considerable security requirements in website design.

  • DES-A SHOULD

    The Website should be designed based on secure software development and management standard V.1 requirements.

  • DES-B SHOULD

    The Website design document should be reviewed and approved by the respective responsible body of the organizations.

2.3 Implementation 3 mandatory 5

The objective of this focus area is to provide security requirements for coding and testing of the website.

  • IMP-A SHOULD

    The Website should be implemented based on secure software development and management standard V.1 requirements.

  • IMP-B SHOULD

    Website developers should sufficiently be aware of security requirements of the organization.

  • IMP-C MUST

    Organizations must ensure that their website is awarded accreditation before hosted based on Critical Mass Cyber Security Requirement Standard Version 1.0.

  • IMP-D MUST

    The website must be audited before hosted based on the auditing Process defined in the Critical Mass Cyber Security Requirement Standard.

  • IMP-E MUST

    All documentation must adequately be protected from unauthorized access.

2.4 Hosting 5

The Website hosting security requirement intends to proactively manage security issues related to the hosting services.

  • HOS-A SHOULD

    The organization should prepare a comprehensive hosting security requirement document that comprises technical and non-technical issues before hosting its website.

  • HOS-B SHOULD

    Website hosting security requirements document should examine the hosting service provider's security capability in terms of technical parameters including but not limited to:

    1. Staff capability of hosting service provider
    2. Network infrastructure security
    3. System infrastructure security including the server operating system, hosting platform
    4. Implemented Communication encryption tools
    5. Business continuity plan
    6. Disaster recovery capability
    7. Physical security
  • HOS-C SHOULD

    Website hosting security requirements document should examine hosting service provider's security capability in terms of non-technical parameters including but not limited to:

    1. The most recent third-party security audit reports on the hosting service provider
    2. Business processes of the hosting service provider
  • HOS-D SHOULD

    Government websites should be hosted on organization premises or on hosting entity infrastructure deployed in Ethiopia.

  • HOS-E SHOULD

    Separate comprehensive security agreements should be signed between the organization and the hosting service provider which comprise the following provisions:

    1. Roles, Responsibility, and accountability of the contracting parties
    2. Breach handling procedures and responsibilities
    3. Exceptional events
    4. Expected service levels
    5. Communication methods
    6. Not complying with National Standards, Regulations, and other related legal mandates
    7. Service contacts
    8. Data limits
    9. Bandwidth limits
    10. Downtime limits
    11. Domain namespaces scalability and changes
    12. Ability to unlink for any violations of law or regulation, breach or violation of any contract provisions
2.5 Operation and Management 3 mandatory 15

The Objective of this focus area is to set requirements on how to manage all security anomalies faced during operations.

  • OPM-A SHOULD

    Organizations should have clear policy statements, to manage their organizational websites. Organizational Website policies should address at least the following points:

    1. Administrative Responsibilities
    2. Emergency communications
    3. Contents management
  • OPM-B SHOULD

    Organizations Website management and operation activities should be conducted based on documented procedures.

  • OPM-C SHOULD

    Website access rights provisions should be granted and revoked formally via documented procedures.

  • OPM-D SHOULD

    Website access privileges should be categorized based on business requirements and the website policy of the organization.

  • OPM-E SHOULD

    Organizational Access credentials should be updated in a fixed time frame and whenever there is change in structure or strategic mission.

  • OPM-F SHOULD

    Organizations should conduct security vulnerability and risk assessments on their website quarterly.

  • OPM-G SHOULD

    Additional security testing should be undertaken as deemed necessary by risk assessment reports.

  • OPM-H SHOULD

    Periodic testing and auditing should be performed to ensure the on-going effectiveness of website security controls as new threats emerge.

  • OPM-I MUST

    Website changes, including updates and patches, must be reviewed and tested to ensure that there is no adverse impact on the operation. This includes:

    1. Formal change control procedures must be established and documented, and evidence retained that the procedure is implemented and complied with
    2. Changes must be approved by the cyber security department
  • OPM-J MUST

    When significant changes or enhancements are made, in advance operational risk assessment must be performed to consider the security implications of such changes.

  • OPM-K SHOULD

    Website monitoring tools should be implemented to detect breaches or misuse of web applications.

  • OPM-L SHOULD

    The organization should have proper patch and configuration management plans for its website.

  • OPM-M MUST

    The patch and configuration management process must be tested on separate environment before implemented on the functional site.

  • OPM-N SHOULD

    The organizations should continuously ensure communication encryption certificate updates of its website.

  • OPM-O SHOULD

    The organization should follow and monitor periodic security updates and changes of the hosting service provider.

Common Vulnerabilities & Threats

Annex A — vulnerabilities that must be considered during design, implementation, hosting, operation and management

NoVulnerabilityPossible threats
1 SQL Injection
  • Bypass login authentication
  • Disclosure of sensitive data stored in the database
  • System shutdown
2 Unchecked Path Parameter / Directory Traversal
  • Disclosure of sensitive information
  • Falsification and deletion of configuration files, data files and source codes
3 Improper Session Management
  • Unauthorized access to personal information
  • Webmail
4 Cross-Site Scripting
  • Confusion caused by false information
  • Disclosure of sensitive information through phishing attacks
  • If the session ID is stored in the stolen cookie, it could lead to spoofing
  • If personal information is stored in the stolen cookie, the sensitive data would be disclosed
5 CSRF (Cross-Site Request Forgery)
  • Access the services normally available only for the users who have properly logged in
6 HTTP Header Injection
  • When an HTTP Set-Cookie header is inserted, an arbitrary cookie is created and stored in the user's browser
7 Mail Header Injection
  • Used as a launching pad for the spam distribution
8 Lack of Authentication and Authorization
  • Disclosure of sensitive information
